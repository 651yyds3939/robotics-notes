# AI、VLA 与数据工程：从采集到真机闭环

> **定位**：模型架构回答“策略怎么学”，本专题回答“数据是否可信、实验能否复现、模型能否安全兼容地部署，以及真机失败如何回流”。
>
> 核心闭环：**任务定义 → 数据采集与治理 → 训练与评测 → 模型制品 → 真机部署 → 运行监控 → 困难样本回流 → 再训练与发布**。
>
> 相关入口：[全链路思维导图](../robot_system.md) · [VLA 研究版图](./vla_landscape.md) · [Benchmark 与 Dataset](./benchmark_dataset.md) · [边缘模型部署](./edge_deployment.md) · [系统工程](./systems_engineering.md) · [安全工程](./safety_engineering.md)

## 一、为什么需要 AI/VLA 工程闭环

一个策略在离线数据或少量 Demo 上成功，不等于它能在整机上长期运行。工程问题通常出现在模型之外：

- 相机、关节状态和 action 的时间戳未对齐。
- 训练集和测试集含同一条轨迹的相邻片段，评测结果虚高。
- 权重正确，但归一化、关节顺序、action scaling 或标定版本错误。
- VLA 输出不可达、过期或不连续动作，却直接进入执行器。
- 新模型没有回归门槛、灰度发布和回滚路径。
- 真机失败没有保留上下文，无法判断问题来自感知、策略、规划还是控制。

因此，AI 系统的最小版本单位不应只是一个 checkpoint，而应同时包含数据、代码、配置、本体、标定、评测和部署契约。

## 二、任务定义与验收指标

### 2.1 先定义任务和运行边界

对每个任务明确：

- 输入：语言、图像、深度、关节状态、力觉及历史窗口。
- 输出：技能、末端位姿、短轨迹、关节位置或其他 action 表示。
- 场景：物体集合、初始位姿、背景、光照、遮挡、载荷和人员接近条件。
- 完成条件：成功、部分成功、失败和超时如何判定。
- 失败处理：重试、重新观察、换抓取点、回安全位或请求人工接管。
- 禁止行为：碰撞、越界、掉落、过力、进入禁区和绕过安全层。

### 2.2 不要只看训练 loss

| 层级 | 典型指标 |
|------|----------|
| 模型/离线 | validation loss、动作误差、语言/目标识别准确率 |
| 动作质量 | 轨迹连续性、变化率、越界率、被安全层拒绝率 |
| 仿真任务 | 成功率、碰撞率、超时率、长视野完成率 |
| 真机任务 | 成功率、完成时间、重试率、人工接管率、安全触发率 |
| 系统性能 | 推理 P50/P95/P99 延迟、数据年龄、显存峰值、超时率 |

指标应按任务难度和运行设计域分层统计，避免把简单场景的平均成功率当成整体能力。

## 三、数据契约与采集管线

### 3.1 Episode 数据契约

一次 episode 至少定义：

| 类别 | 内容 |
|------|------|
| 观测 | RGB/深度、关节位置/速度、末端状态、力觉、触觉 |
| 指令 | 原始语言、解析后的任务 ID、目标对象和约束 |
| 动作 | action 表示、单位、坐标系、控制模式和执行频率 |
| 时间 | 硬件/系统时间戳、同步误差、丢帧与数据有效性 |
| 结果 | 成功、失败、超时、人工终止和失败原因 |
| 版本 | 机器人、URDF、标定、采集软件、遥操作设备和配置 |

所有字段需要说明单位、坐标系、数据类型、形状、合法范围、频率和缺失值处理。Schema 变更应提升版本并提供迁移或兼容策略。

### 3.2 多模态时间同步

相机 30 Hz、策略 10–50 Hz、机器人状态数百 Hz、力觉 1 kHz 时，必须明确：

- 统一时钟源及跨机同步误差。
- 以观测时刻、action 生成时刻还是实际执行时刻建立样本。
- 最近邻、插值、窗口聚合或采样保持策略。
- 采集、传输、推理和执行延迟是否单独记录。
- 丢帧、乱序、重复帧和过期数据如何标记，而非静默填补。

### 3.3 采集前检查

- 相机内外参、IMU、关节零位和力传感器已标定。
- 机器人、URDF、关节顺序、控制模式和 action 范围一致。
- 录制端磁盘、带宽、帧率和时间同步满足要求。
- 遥操作映射、缩放、夹爪语义和坐标变换经过验证。
- 安全状态、隔离区、限速限力和人工终止通道可用。

## 四、数据质量与治理

### 4.1 自动质量检查

每次采集后执行可自动化的检查：

- 图像黑帧、模糊、冻结、重复帧、曝光异常和分辨率变化。
- 状态/action 中的 NaN、缺失、越界、突变、饱和和时间倒退。
- 观测与 action 的频率、延迟、对齐误差和丢帧比例。
- episode 长度异常、空动作、错误终止和重复轨迹。
- 机器人、关节数量、名称、单位和标定版本不匹配。

质量检查结果本身也应作为数据集制品保存，并定义拒收、人工复核和可接受降级规则。

### 4.2 标签和失败分类

除了成功/失败二值标签，建议建立分层原因：

```text
感知：目标漏检 / 遮挡 / 位姿错误
任务：语言误解 / 技能选择错误 / 前置条件不满足
策略：动作方向错误 / 抖动 / 停滞 / 分布外
规划控制：不可达 / 碰撞 / 跟踪误差 / 限幅
硬件系统：夹爪 / 标定 / 通信 / 过温 / 欠压
人员流程：人工终止 / 操作错误 / 场景配置错误
```

分类应允许多标签，并区分首因与最终现象。

### 4.3 数据版本与血缘

一个数据集版本应能够回答：

- 来源于哪些原始 episode，经过哪些过滤、裁剪、重采样和标注。
- 使用哪个转换脚本、代码提交、依赖和配置生成。
- 对应哪些机器人、标定和数据 Schema 版本。
- 谁审核、何时发布、已知问题和适用任务是什么。

原始数据尽量不可变；清洗结果通过派生版本生成，禁止直接覆盖后失去血缘。

### 4.4 训练/验证/测试划分

- 按 episode、场景、物体或采集批次划分，不能按相邻 frame 随机切分。
- 测试集与训练调参隔离；公开 Benchmark 按官方协议执行。
- 单独维护分布外集合：新物体、新背景、新光照、新语言表达和新初始位姿。
- 困难样本可以进入训练，但保留独立回归集合防止遗忘和指标污染。

### 4.5 隐私与授权

涉及人脸、声音、家庭/工厂环境和操作者信息时，需要明确采集授权、用途、访问控制、脱敏、留存周期、导出和删除流程。

## 五、训练与实验追踪

### 5.1 可复现实验

每个实验至少绑定：

```text
代码提交 + 依赖/容器 + 数据集版本 + 训练配置
+ 基础模型/Tokenizer + 随机种子 + 本体与 action 定义
```

记录超参数、硬件、训练时长、吞吐、checkpoint、指标和异常。最终模型必须能从记录中重建，而不是只剩一个无法解释的权重文件。

### 5.2 训练制品

- 基础模型和微调权重。
- 优化器/调度器状态与断点续训信息。
- 观测与 action 的归一化统计。
- Tokenizer、词表、图像预处理和历史窗口配置。
- 训练/验证曲线、最佳 checkpoint 选择规则和已知失败模式。

### 5.3 数据混合与跨本体训练

跨机器人或多数据源训练时，显式记录：

- 各数据源采样权重和去重策略。
- 本体、相机、action space 与语言标签的映射。
- 绝对/相对、关节/末端、位置/速度等 action 表示差异。
- 缺失模态、不同频率和不同成功标签的处理。
- 各本体和任务的分项指标，避免大数据源掩盖小数据源退化。

## 六、分层评测与发布门槛

### 6.1 评测阶梯

```text
数据/Schema 检查
→ 离线回放评测
→ 仿真与 Benchmark
→ Shadow/无执行观察
→ 受保护真机低速测试
→ 场景回归
→ 小范围灰度
→ 正式发布
```

- **离线回放**：固定输入对比新旧模型输出，定位模型本身的变化。
- **仿真评测**：扩大随机场景并注入延迟、噪声、遮挡和动力学偏差。
- **Shadow 模式**：模型产生建议但不接管执行，比较实际动作和策略动作。
- **真机评测**：验证低层跟踪、接触、硬件约束和真实失败恢复。

### 6.2 回归门槛

发布门槛至少包含：

- 核心任务成功率不低于基线要求。
- 安全违规、碰撞、越界和人工接管不超过阈值。
- 关键场景、长尾场景和历史事故用例不退化。
- 推理延迟、显存、稳定性和长时间运行满足资源预算。
- 模型与目标机器人、传感器、URDF、标定和 Runtime 兼容。

平均指标提升不能自动抵消严重安全回归。

### 6.3 失败归因

将整机任务拆成可观测阶段：

```text
语言理解 → 目标感知 → 技能选择 → 动作生成
→ 可行性/安全过滤 → 低层跟踪 → 接触结果 → 任务确认
```

每阶段记录输入、输出、置信度、耗时和错误码，避免把所有失败笼统归因于“VLA 不行”。

## 七、模型制品与兼容契约

### 7.1 模型包而非裸权重

推荐模型发布包至少包含：

```text
policy_package/
├── model.onnx                 # 或 TensorRT / 原生 checkpoint
├── metadata.yaml              # 模型、代码、数据和任务版本
├── io_schema.yaml             # 输入输出名称、形状、单位和语义
├── preprocessing.yaml         # 图像与语言预处理
├── normalization.npz          # 状态/action 归一化统计
├── joint_mapping.yaml         # 关节名称、顺序、方向和缩放
├── compatibility.yaml         # 本体、传感器、URDF、Runtime 范围
├── evaluation_report.json     # 回归指标与发布结论
└── checksums.txt              # 完整性校验
```

具体格式可按项目调整，但不能丢失语义、兼容性和评测证据。

### 7.2 启动前校验

- 模型、Runtime、算子集和精度模式兼容。
- 图像尺寸、颜色空间、相机顺序、裁剪和归一化一致。
- 状态字段、关节名称/顺序、单位、方向和历史窗口一致。
- action 类型、坐标系、缩放、限值和控制模式一致。
- 机器人型号、URDF、标定和配置哈希位于允许范围。

校验失败应拒绝使能模型，不应靠警告后继续运行。

### 7.3 发布与回滚

- 模型制品不可变、带版本、签名或校验和。
- 开发、候选、灰度、正式和退役状态明确。
- 灰度发布限制机器人、场地、任务、速度或使用时段。
- 保留上一稳定版本和一键回滚路径。
- 模型、代码、配置和数据迁移作为一个发布单元评审。

## 八、VLA 运行时架构

### 8.1 明确输出层级

```text
语言/视觉
→ VLA / 任务模型
→ 技能或短期动作目标
→ 行为树/状态机/运动规划
→ IK/WBC/伺服
→ 驱动器
```

VLA 可以输出技能、末端位姿、action chunk 或关节动作，但每种输出都需要明确频率、时域、坐标系、有效期、可取消性和低层接口。大模型不应绕过控制权仲裁与安全链直接驱动执行器。

### 8.2 多速率与动作有效期

- 语言规划、视觉策略、运动规划和伺服控制按各自频率运行。
- 每个动作携带生成时刻、目标执行时刻、有效期和序列号。
- 推理超时、观测过期或新任务取消后，旧动作必须失效。
- action chunk 执行期间持续接受状态反馈和安全否决，而非开环播完。
- 切换模型、技能或控制器时采用握手、插值和速率限制。

### 8.3 前置条件、后置条件与恢复

每个技能定义：

- **前置条件**：目标可见、位姿可信、机械臂可用、路径可规划、夹爪状态正确。
- **执行监控**：进度、超时、目标漂移、接触和安全过滤结果。
- **后置条件**：是否真正抓住、放置成功或完成导航，而不是只判断动作已发送。
- **恢复策略**：重新观察、重新规划、调整抓取点、退回安全位、重试上限和人工接管。

### 8.4 安全与可行性过滤

VLA 输出进入低层前至少经过与任务匹配的：

- 工作空间、关节限位、速度/加速度/变化率约束。
- IK 可达性、自碰撞/环境碰撞和奇异性检查。
- 力、力矩、功率、接触与禁区约束。
- 控制模式和控制权合法性检查。
- 分布外、低置信度、输入缺失和推理异常处理。

详见[安全工程](./safety_engineering.md)。

## 九、部署性能与运行可观测性

### 9.1 部署验收

除了模型精度，还要测试：

- 冷启动、模型预热和首帧延迟。
- P50/P95/P99/最大推理延迟和 deadline miss。
- CPU/GPU/NPU、显存、内存、功耗和温度。
- CUDA OOM、模型加载失败、Runtime 崩溃和资源争用。
- 输入中断、相机重连、网络抖动和长时间运行。
- 过载时降频、丢弃旧帧、暂停 AI 或退回基础技能的策略。

模型转换和推理后端细节见[边缘模型部署](./edge_deployment.md)。

### 9.2 在线指标

- 输入频率、数据年龄、缺帧、模糊和分布外比例。
- 各模型/技能推理频率、延迟、错误和资源占用。
- action 越界、限幅、安全拒绝和控制器跟踪误差。
- 任务成功、超时、重试、恢复、人工接管和安全触发。
- 当前机器人、模型、标定、配置和软件版本。

### 9.3 AI 黑匣子

故障触发时固化：

- 事件前后的关键图像、状态、语言和历史窗口。
- 模型原始输出、过滤后目标和实际执行反馈。
- 任务/技能状态、控制权、安全拒绝原因和错误码。
- 模型包、URDF、标定、配置、软件和硬件版本。

需根据隐私、存储和安全要求设计采样率、留存时间和访问权限。

## 十、困难样本回流与持续改进

### 10.1 闭环流程

```text
真机失败/低置信度/人工接管
→ 自动固化上下文
→ 首因分类与人工复核
→ 困难样本池
→ 补采、修标、重加权或改算法
→ 离线/仿真/历史事故回归
→ 受保护真机验证
→ 灰度发布与持续监控
```

不是所有失败都应该直接进入训练集：标定错误、硬件故障、错误标签和系统接口问题应先修复根因，避免模型学习补偿错误系统。

### 10.2 防止闭环污染

- 保留不可变的原始数据和独立测试集。
- 记录样本为什么被选入、如何重标和进入哪个数据版本。
- 避免只回流失败样本造成新分布偏斜。
- 检查新模型是否遗忘原有任务或只记住事故用例。
- 数据、模型、评测和发布变更保持双向追溯。

## 十一、职责与核心交付物

### 11.1 典型职责

| 角色 | 主要责任 |
|------|----------|
| 产品/任务 | 任务定义、场景边界和验收指标 |
| 数据工程 | Schema、采集、质量、版本、权限和血缘 |
| 算法/研究 | 模型、训练、离线评测和失败分析 |
| 平台/MLOps | 实验追踪、制品库、CI、发布和回滚 |
| 机器人系统 | 接口、时间同步、本体兼容、运行时和可观测性 |
| 控制/安全 | 动作可行性、低层约束、安全过滤和真机验收 |
| 测试/运维 | 场景回归、灰度监控、事件复盘和现场回流 |

### 11.2 最小交付物

- 任务规范、场景矩阵和验收阈值。
- 数据 Schema、采集 SOP、质量报告和数据集卡。
- 数据血缘、训练配置、实验记录和模型卡。
- 离线/仿真/真机评测报告与历史事故回归结果。
- 模型包、I/O 契约、兼容性矩阵和校验和。
- 部署、监控、灰度、回滚和故障恢复方案。
- 困难样本池、失败分类与再训练变更记录。

## 十二、落地检查表

### 数据采集前

- [ ] 任务、成功/失败、场景边界和禁止行为已定义。
- [ ] 数据字段、单位、坐标系、频率、时间戳和 action 语义已冻结。
- [ ] 机器人、URDF、关节顺序、标定和采集软件可追溯。
- [ ] 时间同步、磁盘、带宽、安全终止和采集质量检查已验证。

### 训练与评测前

- [ ] 原始数据不可变，清洗和标注有版本与血缘。
- [ ] 训练/验证/测试按 episode 或场景隔离，无明显泄漏。
- [ ] 代码、依赖、数据、配置、随机种子和基础模型可复现。
- [ ] 核心、长尾、分布外和历史事故场景有明确回归门槛。

### 真机发布前

- [ ] 模型包包含预处理、归一化、I/O、关节映射和兼容契约。
- [ ] 启动校验能阻止错误本体、标定、Runtime 或 action 配置使能。
